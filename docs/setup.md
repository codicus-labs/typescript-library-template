# Setup decisions

## Scope and decision (2026-09-24)

The first milestone is text → validated item movement → durable event/provenance → deterministic location/history queries. **This setup does not implement it.** Build that vertical slice next, before adding other domains or generic framework machinery.

- **Runtime / packages:** Node 24 LTS, pinned to 24.21.0; pnpm 12.4.2; one private ESM package. Separate packages have no demonstrated benefit yet. The developer shell currently runs Node 26, so select the pinned version before running checks. [Node release schedule](https://nodejs.org/en/about/previous-releases).
- **Language / tests:** strict TypeScript 7, Vitest 5 and Zod 4. The installed versions are recorded in `pnpm-lock.yaml`. The quality gate runs TypeScript, type-aware Oxlint, Oxfmt, Knip and Vitest. Commitlint and lint-staged are available through optional Git hooks; no `@codicus/configs` preset is used. [TypeScript](https://www.typescriptlang.org/), [Vitest requirements](https://vitest.dev/guide/migration/), [Zod](https://zod.dev/).
- **Storage (planned):** SQLite via Node's built-in `node:sqlite`, with explicit SQL and transactions rather than an ORM. It is a release-candidate API on Node 24, so reassess if its limitations show up in the slice. SQLite can preserve history and support deterministic local queries without a service; enable foreign-key enforcement per connection. PostgreSQL, vectors and graph storage are deferred. [Node SQLite API](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html), [SQLite foreign keys](https://sqlite.org/foreignkeys.html).
- **Local inference (planned):** Ollama's local OpenAI-compatible API (`http://localhost:11434/v1`) is the initial runtime because Ollama is already running on this Apple Silicon machine. It exposes schema-constrained structured output, but actual model/schema compatibility and semantic accuracy are unverified. LM Studio is another local OpenAI-compatible option; do not introduce a second runtime yet. [Ollama structured output](https://ollama.com/blog/structured-outputs), [Ollama OpenAI compatibility](https://ollama.com/blog/openai-compatibility), [AI SDK compatible providers](https://ai-sdk.dev/providers/openai-compatible-providers).
- **AI integration (planned):** put AI SDK `generateText` + `Output.object` and `@ai-sdk/openai-compatible` in a single adapter behind an application-owned extractor interface. Validate output with Zod and use a fake extractor in deterministic tests. Do not couple domain logic to Ollama, the SDK, or a chosen model. Install these dependencies when implementing the adapter, not before. [AI SDK structured data](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data).
- **Laya (deferred):** a community MLX port offers local typed `choice`, `score` and `noul` decisions on Apple Silicon via Python. It is not a generative extractor or a required V1 component; its benchmarks are not measurements on this M5 Pro. Evaluate only against a concrete resolution/acceptance decision benchmark. [Laya MLX runtime](https://github.com/mizorewww/laya-mlx).

## Deviations and risks

No monorepo, schema DSL, ORM, PostgreSQL, Laya service or second domain yet. Existing Ollama models are _candidates_, not a benchmark-backed selection. The setup test verifies tooling and runtime validation only; local inference, database behavior, extraction accuracy, latency and memory remain to be measured in the vertical slice. Corrections and ambiguous item names must not silently mutate trusted state.
